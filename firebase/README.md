# Firebase Realtime Database rules — โปรเจกต์ `gps-photo-app-19249`

ไฟล์ `database.rules.json` ใช้กับฐานข้อมูลที่ระบบเช็คอิน (`checkin-nophoto.html`, `parent-status.html`) ใช้ร่วมกับแอปอื่นของโปรเจกต์นี้
(**ผมแก้ใน Firebase ให้เองไม่ได้ — ต้องให้คนที่มีสิทธิ์ใน Firebase Console นำไปวางตามขั้นตอนด้านล่าง**)

## สิ่งที่ rules นี้ทำ
| ส่วน | กติกา |
|---|---|
| `checkin2_meta` (บันทึกเช็คอิน) | **สร้างใหม่ได้อย่างเดียว** — แก้ทับ/ลบ/ปลอมแก้ของเดิมไม่ได้ · ตรวจรูปแบบข้อมูล (รหัสนักเรียน 11 หลัก, พิกัดอยู่ในช่วง, ชื่อไม่ว่าง ฯลฯ) · ไม่รับฟิลด์แปลกปลอม (รองรับ `by:'teacher'`/`why` สำหรับครูเช็คอินแทน) · เวลา (`ts`) ต้องอยู่ในช่วง −2 วัน…+10 นาที จากเวลาเซิร์ฟเวอร์ (กันย้อนเวลา) · มี index `ts`, `sid` ให้ดึงเฉพาะช่วง/เฉพาะคนได้ (ประหยัดโควตาดาวน์โหลด) |
| `checkin2_void` (ยกเลิกรายการ) | ครูกด "ยกเลิก" รายการที่เช็คอินแทนผิดคน → สร้างตัวมาร์กได้อย่างเดียว (ยกเลิกการยกเลิก/ลบ/แก้ไม่ได้) รายงานและหน้าผู้ปกครองไม่นับรายการที่ถูกยกเลิก |
| `checkin2_photo` (รูป) | สร้างใหม่ได้ · **ลบได้** (ใช้กับปุ่ม "ลบรูปเก่า") · แก้ทับไม่ได้ · ต้องเป็น JPEG data URL ขนาดไม่เกิน ~400 KB |
| `checkin2_config`, `checkin2_rounds` | อ่าน/เขียนได้ (ครูตั้งเส้นตาย รอบเช็คอิน ตัวเลือกต่าง ๆ ผ่านหน้าเว็บ) |
| path ของแอปอื่น (`submissions`, `general_visits`, `meditation`, `motherday-submissions`, `scout-users`, `homecheckin_*`) | **เปิดเหมือนเดิม** เพื่อไม่ให้แอปเหล่านั้นพัง |
| path อื่นที่ไม่ได้ระบุ + ราก (`/`) | **ปิดทั้งหมด** (กันลบ/เขียนทั้งฐานข้อมูล) |

## ขั้นตอนใช้งาน (ทำครั้งเดียว)
1. เปิด Firebase Console → โปรเจกต์ `gps-photo-app-19249` → **Realtime Database** → แท็บ **Data**
   - ดูรายชื่อ key ระดับบนสุด ถ้ามี key ที่ **ไม่อยู่ในตารางด้านบน** ให้เพิ่มบรรทัด `"ชื่อ": { ".read": true, ".write": true }` ในไฟล์ก่อน ไม่งั้นแอปที่ใช้ key นั้นจะใช้ไม่ได้
2. แท็บ **Rules** → **คัดลอกกฎเดิมเก็บไว้ก่อน** (เผื่อย้อนกลับ) → วางเนื้อหาของ `database.rules.json` → **Publish**
3. ทดสอบทุกแอปที่ใช้ฐานข้อมูลนี้: หน้าเช็คอิน (ส่งเช็คอิน 1 ครั้ง, เปิดหน้ารายงาน, หน้าผู้ปกครอง), `gps-photo-app.html`, `home-visit-general.html`, `scout69/*`, `scout-good-deeds`, `checkin.html`
4. ถ้าแอปไหนใช้ไม่ได้ → วางกฎเดิมกลับทันที แล้วแจ้งผู้ดูแลเพื่อเพิ่ม path ที่ขาด

หน้าเว็บมี fallback: ถ้ายังไม่ได้ตั้ง index จะดึงข้อมูลทั้งหมดแทน (ช้ากว่า/กินโควตามากกว่า แต่ไม่พัง)

## ทดสอบ rules ด้วย Emulator (ไม่ต้องแตะฐานข้อมูลจริง)
```bash
cd firebase
npx firebase-tools emulators:exec --only database --project demo-checkin "node rules-test.js"
```
(ต้องมี Node.js + Java) ผลล่าสุด: **43 ผ่าน / 0 ไม่ผ่าน** — ครอบคลุมการเช็คอินปกติ, การแก้ทับ/ลบ, ข้อมูลผิดรูปแบบ, เวลาย้อนหลัง, รูป, การตั้งค่าของครู, การเช็คอินแทนและการยกเลิกโดยครู, query แบบมี index และ path ของแอปอื่น

## สิ่งที่ rules นี้ **ยังไม่ได้ป้องกัน** (ต้องใช้ Firebase Authentication เพิ่ม)
- **ทุกคนยังอ่านข้อมูลได้** รวมถึงพิกัดและรูปนักเรียนใน `checkin2_meta`/`checkin2_photo` (หน้าผู้ปกครองและหน้านักเรียนต้องอ่านข้อมูลนี้)
- `checkin2_config`/`checkin2_rounds` ยังเขียนได้ทุกคน (เพราะรหัสครู `2569` ตรวจฝั่งเบราว์เซอร์เท่านั้น) — คนที่รู้โครงสร้างสามารถเปลี่ยนเส้นตาย/เปิดรอบปลอมได้
- ใครก็ลบรูปได้ (ปุ่มลบรูปเก่าใช้สิทธิ์เดียวกัน)
- นักเรียนเช็คอินแทนกันยังเป็นไปได้ถ้าหลบ "ผูกเครื่อง" (ล้างข้อมูลเบราว์เซอร์/ใช้เครื่องอื่น)

ถ้าต้องการป้องกันส่วนเหล่านี้จริง แนะนำขั้นถัดไป: เปิด Firebase Authentication (อีเมล/รหัสผ่านสำหรับครู) แล้วให้ครูล็อกอินก่อนเขียน config/rounds, ลบรูป, อ่านพิกัด/รูป และแยกพิกัดไปไว้ path ที่ครูอ่านได้เท่านั้น — ต้องมีคนเปิดบริการใน Console และให้ API key ของโปรเจกต์

## เรื่องข้อมูลส่วนบุคคล (PDPA)
ระบบเก็บชื่อ รหัสนักเรียน เวลา พิกัด และ (ถ้าเปิด) รูปของผู้เยาว์ ควรแจ้งวัตถุประสงค์ให้นักเรียน/ผู้ปกครองทราบ ใช้เฉพาะการเช็คชื่อ และลบรูป/ข้อมูลที่ไม่จำเป็นเป็นระยะ
